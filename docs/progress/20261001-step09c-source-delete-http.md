# 단위 09-C — 소스 논리 삭제 HTTP 연결

작성일: 2026-10-01 · 코드·로컬 검증 완료 · 서버 HTTP 격리 검사 대기

## 선행 결과와 범위

AGENTS.md·작업 기준·09-B 기록과 사용자 서버 로그를 확인했다. 09-B 패치 적용 및 PostgreSQL 17.11의 실제 최소 권한·동시 삭제/수정·롤백/재시도 검사가 통과했고 시험 자원 정리가 끝났다. 상세 인수 결과는 [09-B 기록](20261001-step09b-source-delete-storage.md)에 추가했다.

이번 단위는 **소스 DELETE HTTP 연결·등록 전용 사용 정책·필수 검증·전달**이다. 운영 camera는 0.5.0-source-update·스키마 5다. 새 HTTP 코드 0.6.0-source-delete는 09-B의 스키마 6을 요구하지만 이번 패치는 운영 이미지를 바꾸거나 DB를 마이그레이션하지 않는다. 기존 저장소 코드·마이그레이션 0001~0006·권한·운영 Compose·이미지 고정·전환 도구는 유지한다.

## 구현

- DELETE /api/v1/sources/{source_id}를 09-B DeleteSource와 연결했다. 인증 → 메서드 → 쿼리 → 경로 → 조건 헤더 → 키 → media/JSON → 의미 → 저장소 순서를 유지한다. 빈 쿼리 구분자도 거부한다. 일반 단건 경로 Allow는 GET, PATCH, DELETE이며 소문자 validate와 동등한 URL 이스케이프는 기존 POST 전용 예약 경로를 유지한다.
- SourceDelete에 엄격한 디코더를 추가했다. 두 필드만 허용하고 버전은 부동소수점 변환 없이 int64 원문 정수로 읽는다. 중복/이스케이프 중복 키·미지/대소문자 필드·잘못된 타입·실수/지수·범위 초과·null·무효 UTF-8·후행 JSON은 거부한다. 누락·0/음수·잘못된 schema_version은 의미 오류로 분리한다. 기존 64 KiB 제한과 조건 헤더 금지·단일 멱등 키 규칙을 적용한다.
- 응답은 별도 SourceDeletion 영수증과 DELETED/runtime_verified=false/request_id다. 최초와 재생 모두 200, Idempotency-Replayed는 false/true, Location은 없고 no-store 및 매 요청의 새 ID를 유지한다. SOURCE_IN_USE는 409, SOURCE_USAGE_UNAVAILABLE는 503으로 연결했다.
- app 생성자와 camera-api 시작 코드를 확인했다. 현재 설치 경로에는 메타데이터 등록·조회·수정·검증만 있고 세션·consumer·미디어 어댑터 생성자나 활성화 설정이 없다. 서버 내부에서 registry-only-v1 정책을 명시적으로 선택하고 검토한 capability 목록과 값이 모두 일치할 때만 미사용을 반환한다. 누락·새 항목·런타임 기능 활성·알 수 없는 모드는 거부한다. 클라이언트·환경에서 정책을 선택하지 못하며 force/cascade/purge/restore도 입력으로 허용하지 않는다.
- 등록 전용 정책은 외부 미디어의 사용 여부 탐지가 아니다. 실제 세션·소비 관계·어댑터 도입 전에는 이 전제를 폐기하고 같은 소스 행 잠금과 결합된 사용 입장 제어를 구현해야 한다. 이 경계를 코드와 계약에 명시했다.
- 새 manifest와 실행 OpenAPI에 소스 삭제 기능·독립 응답 스키마를 추가했다. 기존 SourceResponse는 보존한다. 서버 격리 검사 scope는 camera_source_delete_http_native_postgresql이다. 사용자 실행 명령은 채팅에서 별도로 전달한다.

## 검증

- Go 1.27.1 전체 패키지 race 검사와 go vet 통과. DB 환경이 없는 검사에서 skip된 통합 검사를 DB 성공으로 계산하지 않았다.
- 별도 임시 PGlite 18.3에서 실제 camera API 프로세스를 통한 app 통합 검사 통과. 삭제 결과·논리 삭제/버전/시각, 프로필/부모/형제 보존, GET/목록 제외와 삭제 전 cursor 사용, ID/채널 재사용 거부, 과거 POST/PATCH/DELETE 결과 재생, JSON/URL 정규화, 키/버전 충돌·최댓값, 예약 경로를 확인했다. API 재시작·토큰 교체 후에도 삭제 결과와 기존 생성/수정 이력이 보존됐다.
- 삭제 성공 기록 쓰기를 의도적으로 실패시킨 HTTP 요청은 503을 반환했고 GET 결과가 원래 상태를 유지했다. 제약을 제거한 뒤 같은 키로 재시도해 최초 성공한 것을 확인했다.
- 등록 전용 정책의 미확인 모드·누락/추가 capability·런타임 활성·취소된 요청 거부와 사용 상태 오류 매핑을 단위 검사로 확인했다. 실제 사용 중 세션을 관측한 검사가 아니다.
- 라우팅/프로세스 smoke 57개 통과. 삭제 인증·키·정수·version·예약 경로와 기존 네 서비스의 실행·정상 종료를 확인했다.
- 삭제 계약 정적 검사 8개, 새 OpenAPI 스키마·예제와 기존 계획 계약의 호환성·내부 참조 확인 통과. 기존 장치 planned 검사 1건의 과거 전제 불일치는 이번 범위에서 변경하지 않았으며 전체 planned 검사를 통과했다고 표시하지 않는다.
- 변경 전후 해시로 storage 전체·기존 마이그레이션·운영 구성/전환 도구 보존을 확인했다. 패키지 payload/압축본 경로·해시, 적용/재적용·충돌 시 부분 쓰기 중단·원본 백업·기존 환경/운영 기록 보존을 확인했다.

실제 PostgreSQL 역할 인증·권한 회수에 따른 HTTP 503/readiness 실패·원자적 롤백/권한 복원 후 동일 키 재시도는 서버 검사에 포함했으며 로컬 PGlite에서는 실행하지 않았다. 09-B 서버 검증은 저장소에 대한 결과이고 이번 새 HTTP 코드의 서버 검증은 아직 대기 중이다. Docker 이미지 전환·실장비·세션·녹화·분석·UI는 검사하지 않았다.

## 서버 결과와 다음 단위

09-B가 적용된 프로젝트에 이번 패치를 적용한 뒤 고유한 임시 Docker 프로젝트에서 검사한다. 운영 환경 파일·DB를 사용하지 않으며 시험 DB 포트는 호스트에 공개하지 않는다. 성공 기준은 status=passed, scope=camera_source_delete_http_native_postgresql, production_services_modified=false와 시험 컨테이너·네트워크 정리다. 서버 결과를 받기 전에는 검증 완료로 기록하지 않는다.

통과 후 다음 단위는 **09-D1: 소스 삭제 운영 전환 사전점검**이다. 현재 운영 0.5.0·스키마 5·이미지/권한/백업 조건을 읽기 전용으로 확인할 도구를 준비한다. 그다음 이미지 리허설·복원/데이터 보존 검증, 실제 운영 활성화로 나눈다. 과거 04~08 활성화 도구를 새 코드에서 재사용하지 않으며 자동 운영 DB 복원은 하지 않는다.
