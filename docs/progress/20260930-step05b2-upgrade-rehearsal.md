## 이번 변경

작업 원칙에 따라 운영 전환의 준비·검사·실행을 한 번에 묶지 않는다. 이번에는 검사 도구, 보호 조건 테스트, 운영 기준, 이 진행 기록만 추가한다. 기존 05-A 프로젝트 명세와 구현 파일은 변경하지 않는다.

별도 무작위 Docker 프로젝트에서 실제 구버전 이미지의 스키마 2를 생성하고 시험 장치·멱등 응답을 저장한다. API 중지 후 백업, 후보 이미지의 스키마 3 및 runtime 권한 반영, 기존 데이터와 새 소스의 조회·멱등 응답·API 재생성 보존을 확인한다. 백업은 별도 DB로 복원해 구버전 API를 실행한다. 새 소스가 존재하는 스키마 3 DB를 복원본으로 덮어쓰지 않는다.

운영 서비스에는 조회만 수행하며 runtime 비밀·데이터는 시험 환경으로 복사하지 않는다. 시험 환경은 별도 포트·비밀·내부 네트워크·볼륨을 사용한다. 세 플랫폼의 시험 컨테이너와 실제 운영 컨테이너의 상태 보존을 확인한다. 시험 자원 정리 실패 시 마운트된 파일을 유지하고 실패로 보고한다. 성공 시 후보 이미지는 후속 전환에서 재사용할 수 있도록 남긴다.

세부 범위와 실패 처리 원칙은 `docs/operations/camera-source-upgrade.md`에 기록했다. 자동 운영 DB 복원이나 운영 전환 도구는 이번 패치에 포함하지 않는다.
