# 단위 09-A — 영상 소스 논리 삭제 계약

작성일: 2026-10-01 · 계약·예제·정적 검사 완료 · 저장소/HTTP 구현 및 운영 활성화 전

## 선행 단계 인수

사용자 서버 로그에서 08 완료 기록 패치 applied, written=1을 확인했다. 백업은 `var/patch-backups/step08-notes-02hj5wkj`, service_restart_performed=false, runtime_activation_required=false다. 단위 08의 소스 표시 이름 수정 구현·검증·운영 전환·완료 기록 반영까지 인수를 마쳤다.

운영 camera는 `0.5.0-source-update`·스키마 5다. 이미지·운영 백업·검증 범위는 [08 완료 기록](20261001-step08-server-acceptance.md)을 따른다. 그 문서의 완료 기록 서버 적용 대기는 이번 로그로 해소됐다. business_runtime_ready=false는 유지한다.

AGENTS.md·작업 원칙·최신 인수 기록을 확인하고 이번 단위를 삭제 계약 하나로 제한했다.

## 확정한 내용

- DELETE 단건 경로에 schema_version·소스 expected_version과 Idempotency-Key를 요구한다. force·cascade·영구 삭제·복원·녹화 삭제는 포함하지 않는다.
- 기존 deleted_at을 쓰는 논리 삭제다. 새 성공은 version+1, deleted_at과 updated_at은 같은 UTC 시각이며 이전 수정 시각보다 과거로 내려가지 않는다.
- 소스 행·프로필·부모/형제·기존 생성/수정 이력을 보존한다. 삭제된 소스는 GET 404·일반 목록 제외이며 source_id와 장치/채널 키를 재사용하지 않는다.
- 삭제 결과는 별도 SourceDeleteResponse의 200 응답이다. 같은 성공 키는 최초 결과를 재생하며, 다른 키의 새 삭제는 삭제된 소스에 404를 반환한다. 과거 생성/수정 재생도 현재 삭제 상태를 복원하지 않는다.
- PATCH/DELETE 경쟁, 같은 키/다른 키 삭제, 버전·키 충돌·최댓값, 원자적 실패와 재시도 규칙을 구분했다.
- 세션·소비 관계나 정리 대기가 있으면 SOURCE_IN_USE, 확인 불가이면 SOURCE_USAGE_UNAVAILABLE이다. 첫 구현·활성화는 사용 관계 생성 기능이 없는 등록 전용 릴리스로 한정하고 전제를 검증한다. 향후 연결 기능에는 삭제와 사용 시작의 원자적 보호가 선행돼야 한다.
- 정확한 validate 예약 경로, 기존 목록 정렬·필터·cursor와 생성/수정 성공 스냅샷을 보존한다.

계약 원본·예제·정적 검사는 camera 소유의 `src/platform/camera/api/planned`에 추가했다. 상세 규칙은 [소스 삭제 계약](../contracts/camera-source-delete.md)에 있다.

## 검증과 한계

- 새 정적 계약 검사 8개 통과: 요청 예제·필수 필드·타입·version 경계, 강제 삭제/비밀/직접 상태 입력 거부, 예약 ID·공백 경계, 삭제 결과와 재생 예제, DELETED 상태와 필수 응답 필드, UTC 시각·삭제 version 범위를 확인했다. 기존 planned/requirements-test.txt의 jsonschema 의존성을 사용한다. 달력상 불가능한 날짜는 선택적 RFC3339 패키지 유무에 의존하지 않도록 표준 라이브러리 검사로 확인한다.
- 기존 planned 검사 전체도 비교했다. 변경 전 24개 중 23개, 변경 후 32개 중 31개가 통과했다. 양쪽의 유일한 실패는 기존 `test_current_openapi_does_not_claim_patch_is_implemented`로, 07-A 당시의 ‘장치 PATCH 미구현’ 전제와 현재 실행 OpenAPI가 맞지 않는 항목이다. 새 계약으로 생긴 실패는 없으며, 이 과거 단계 검사 정리는 별도 정비 항목으로 남긴다. 기존 파일은 수정하지 않았다.
- JSON Schema는 원문 숫자 표기·중복 JSON 키나 실제 삭제·사용 여부·재생·경쟁·DB 권한·원자성을 검증하지 않는다. 이는 후속 저장소/HTTP 검사의 완료 조건이다. 로컬 Python에서 정적 검사를 수행했으며 사용자 서버 Python 3.10에서 새 검사를 실행했다는 뜻은 아니다.
- 새 파일 5개만 추가했다. 기존 Go·실행 OpenAPI·Compose·마이그레이션·프로젝트 명세·08-D1/D2/D3 도구와 기존 파일의 바이트를 유지한다. 현재 OpenAPI와 라우팅에는 소스 DELETE가 없다.
- 패치 적용·재적용·충돌 시 쓰기 중단과 압축본 무결성, 기존 환경·운영 기록 보존을 확인했다. Go/DB 전체 검사·이미지 빌드·서비스 재시작·마이그레이션은 수행하지 않았다.

이번 계약 패치의 서버 적용 결과는 아직 받기 전이다. 적용 명령은 채팅으로만 제공한다.
