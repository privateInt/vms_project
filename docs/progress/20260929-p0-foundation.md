# P0-A HTTP 실행 기반 작업 기록

작성일: 2026-09-29 · 구현 버전: 0.1.0-p0 · 작업 계획: v0.4

## 결과

사용자가 제안한 `src/platform`·`src/infra`·루트 `docs` 구조를 채택하고 작업 기준 문서와 AGENTS에 기록했다. 네 플랫폼의 Go API를 별도 프로세스로 실행하고, CCTV/XR 소스 및 분석 작업의 입력 계약을 검증하는 초기 패키지를 만들었다.

목표 경로 `/home/shshin/workspace/vms_project`는 이번 실행 환경에 존재하지 않아 대상 서버에 직접 설치하지 않았다. 기존 ver1·ver3 코드와 운영 서비스는 변경하지 않았다. 패키지는 별도 환경에서 구현·검증했으며, 기존 파일을 검사하고 충돌 시 중단하는 설치 도구를 포함한다.

## 변경

- camera, model, analysis, operation의 독립 실행 파일·Dockerfile·Compose·OpenAPI를 추가했다. 초기 Go 모듈은 하나이며 업무 코드는 각 플랫폼의 `internal`이 소유한다.
- camera에 `POST /api/v1/sources/validate`, analysis에 `POST /api/v1/analysis-jobs/validate`를 구현했다. 고정 장치·이동 글래스 입력을 같은 소스 개념으로 다루되 ONVIF/PTZ를 XR의 필수 조건으로 만들지 않았다.
- 모델 참조에는 deployment와 고정 model version을 함께 요구하고, 역할 중복·세대 번호·프로필 중복·전송 방식 같은 의미 규칙을 검사한다.
- 개발 토큰 인증, 요청 ID, 본문 크기·Content-Type·입력 검사, JSON 오류, 제한된 구조화 로그, 정상 종료를 공통 HTTP 기반에 추가했다.
- 실제로 없는 기능은 platform manifest에서 planned, 업무 준비 상태는 false로 명시했다. 검증 API는 입력 형식만 확인하며 등록·저장·참조 조회·실행을 하지 않는다.
- `.env` 생성, 실제 프로세스 스모크, 패키지 무결성·기존 파일 충돌 검사 도구를 `src/infra/tools`에 추가했다.
- README, 작업 기준, 두 ADR, 계약 설명, 실행 안내, 전체 작업 계획을 작성·갱신했다.

## 검증 환경과 결과

검증 환경은 Linux amd64, Go 1.27.1, Python 3.12.14다. Go 공식 배포 파일의 SHA-256을 확인한 도구 체인을 사용했다. 모듈의 최소 Go 선언은 1.25.0이며 이 최소 버전에서 별도로 실행한 것은 아니다. 외부 Go 모듈 의존성은 없다.

| 검사 | 결과 | 의미와 한계 |
|---|---|---|
| `go test -race ./...` | 통과 | 공통 HTTP, camera 계약, analysis 계약의 3개 테스트 패키지. 인증·본문 제한·로그·도메인 입력 오류 검증 |
| `go vet ./...` | 통과 | 네 API와 공통·도메인 코드 정적 검사 |
| `smoke.py --launch` | 43개 항목 통과 | 실제 네 Go 바이너리 빌드·실행, HTTP 응답·인증·명세·CCTV/XR 예제·잘못된 입력·SIGTERM 정상 종료 |
| 바이너리 `--healthcheck` | 네 프로세스 통과 | 컨테이너에 사용할 readiness 검사 명령을 네이티브 프로세스에서 실행 |
| Python 설치 도구 단위 검사 | 6개 통과 | 검사 모드 무수정, 재적용·관련 없는 파일 보존, 충돌 시 사전 중단, 변조·경로 이탈·심볼릭 링크 거부 |
| Python·JSON·YAML 구문 | 통과 | 파싱 가능 여부. Docker Compose 실제 기동 검증은 아님 |
| Docker 이미지 빌드·Compose 실행 | 미실행 | 제작 환경에 Docker가 없어 목표 서버에서 확인 필요 |
| 실제 CCTV·XR·TURN·GPU | 미실행 | 관련 기능 미구현, 실제 장비·모델 연결 검증 전 |

스모크 첫 실행에서 상위 작업 환경의 Git 메타데이터를 Go가 읽다가 빌드를 중단했다. 압축 배포에서도 재현 가능하도록 패키지 빌드 명령에 `-buildvcs=false`를 명시한 뒤 재검증하여 통과했다. 이 설정은 VCS 메타데이터를 바이너리에 넣지 않으며 서비스 버전은 코드와 패키지 메타데이터로 기록한다.

## 남아 있는 작업

P0-A의 코드·HTTP 실행 기반은 검증했다. **P0 전체와 P0-T, VMS 업무 기능이 완료된 상태는 아니다.** 다음은 미구현 또는 미확인이다.

1. 대상 서버 설치·Compose 기동, 실제 장치·OS/SDK·GPU·최신 모델 플랫폼 API 확인.
2. 영속 저장소와 플랫폼별 데이터 소유권, Device/Source/Session 등록·삭제·복구·비밀정보 참조.
3. ONVIF 장치·프로필·PTZ, RTSP 수신·중계·플레이어, XR 신호·미디어·TURN·타임스탬프·방향·재접속.
4. 모델 등록·아티팩트·배포·readiness, 추론 어댑터, 분석 job/run/lease·상태 조정·stale 결과 거부.
5. 이벤트·스냅샷·녹화·클립, 운영 업무 조율·UI, 운영 IAM·권한·TLS·감사·관측성.

현재 JSON Schema는 계약 명세이며 서버에 완전한 Schema 실행기를 포함하지 않는다. 도메인 규칙은 Go validator가 담당한다. 프로토콜·모델 실행 가능성은 입력 선언만으로 검증할 수 없으므로 어댑터·런타임 통합 단계에서 확인한다.

## 다음 작업의 완료 기준

다음 구현은 장치·소스·세션 수명과 영속 등록 경로를 확정하는 것이다. 재시작 시 ID 유지, 연결 실패·재연결 시 새 session 부여, 비밀정보의 비노출, 반복 등록·삭제의 멱등성을 확인한다. 이 경계에 맞춰 ONVIF/RTSP와 WebRTC 어댑터를 붙인다. 입력 프레임과 세션·시각 추적을 확보한 뒤 모델 배포와 분석 작업의 실제 연결을 진행한다.
