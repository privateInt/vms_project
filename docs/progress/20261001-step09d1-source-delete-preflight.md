# 단위 09-D1 — 소스 삭제 운영 전환 사전점검

작성일: 2026-10-01 · 사전점검 도구·로컬 검증 완료 · 실제 서버 점검 결과 대기

## 09-C 서버 격리 검사 인수

사용자 로그에서 09-C 패치 applied/written=26을 확인했다. 백업은 `var/patch-backups/step09c-8_et64qr`이며 서비스 재시작·운영 활성화는 수행하지 않았다.

임시 프로젝트 `vms-storage-test-d4d214df0293`의 PostgreSQL 17.11에서 전체 Go race 검사와 vet가 통과했다. 소스 DELETE의 엄격한 입력·정수 토큰·키/조건 헤더·오류 순서·예약 경로, 등록 전용 정책과 오류 매핑을 확인했다. 삭제 결과·버전/키 충돌·최댓값, 부모/형제/프로필·ID/채널 예약 보존, GET/목록 제외와 기존 cursor 사용, 과거 POST/PATCH/DELETE 성공 응답 재생이 통과했다.

실제 API 프로세스 재시작·토큰 교체 후 삭제 결과·과거 이력 보존, runtime 권한 회수 시 DELETE/readiness 503·원자적 롤백·권한 복구 후 같은 키 재시도가 통과했다. 기존 저장소의 스키마 5→6/재적용·사용 상태 거부·시간/버전·최소 열 권한·다중 연결 삭제/수정 경쟁과 장치/소스 HTTP 회귀도 통과했다.

최종 결과는 status=passed, scope=camera_source_delete_http_native_postgresql, production_services_modified=false다. 시험 DB 컨테이너와 네트워크 제거를 확인했다. [09-C 기록](20261001-step09c-source-delete-http.md)의 전달 당시 서버 검사 대기는 이 결과로 해소됐다. 운영 전환 결과가 아니므로 운영은 마지막으로 인수한 08의 `0.5.0-source-update`·스키마 5를 유지한다. 실제 미디어 사용 여부나 실장비를 검증한 것은 아니다.

## 이번 범위

새 `src/infra/tools/inspect_camera_source_delete.py`는 운영 상태를 읽기 전용으로 점검한다. 이번 패치는 도구·해당 Python 검사·이 문서의 3개 파일만 추가한다. 서버에서 검증한 09-C 프로젝트 명세와 기존 모든 파일의 해시를 보존하며 새 파일은 패치 명세로 검증한다. 09-C 명세의 전달 당시 검증 표시도 그대로 유지하고, 이후 서버 인수는 위 기록으로 구분한다. 보고서에는 점검 도구 자체의 해시를 남긴다.

Docker는 프로젝트·컨테이너·볼륨 조회, 현재 Compose 구성 조회와 정확히 지정한 READ ONLY SQL만 허용한다. HTTP는 readiness·platform·소스 목록 GET만 사용한다. 빌드·컨테이너 생성/정지/재시작·마이그레이션·권한 부여·DB 백업/복원·API 변경 요청을 수행하지 않는다. 적용 옵션도 받지 않는다.

로컬 쓰기는 기존 전환 도구와 공유하는 activation 잠금 및 `var/camera/source-delete-preflight.json` 보고서다. 기존 환경·비밀 파일을 생성하거나 고치지 않는다. 성공 보고서도 운영 전환을 허가하지 않으며 후속 리허설·전환 단계에서 상태를 다시 점검해야 한다.

## 확인 항목

- 09-C 코드 버전 0.6.0-source-delete, 스키마 6 저장소 리비전, 소스 삭제 구현·registry-only-v1 정책·업무 런타임 미구현 표시와 프로젝트 명세에 기록된 모든 파일의 SHA-256. 삭제 핸들러·정책·기존 마이그레이션이 필수 확인 대상이다.
- 로컬 Unix Docker, vms-project의 실행 중인 camera API/DB, 기존 영속 볼륨의 소유권과 실제 마운트·DB health.
- 08 완료 기록 `source-update-activation.json`의 activated/completed·스키마 5·source_update_activated 및 현재 API/DB 이미지 일치. 현재 Compose의 camera 이미지도 실행 중인 ID로 고정돼 있어야 한다.
- 기존 비밀 디렉터리/파일 소유권·권한·DSN 형식, 실제 camera 컨테이너의 읽기 전용 runtime DSN 마운트.
- 운영 API 0.5.0-source-update와 P1_SOURCE_UPDATE, 장치/소스 등록·목록·이름 수정 및 계약 검증 기능, 런타임 미구현 capability 목록 전체의 일치. 미디어 기능 활성·세션/소비 기능 추가·누락·알 수 없는 capability는 등록 전용 전제가 달라진 것으로 보고 중단한다. readiness·소스 목록 GET도 확인한다.
- PostgreSQL 17, 마이그레이션 0001~0005의 이름·순서·체크섬 일치와 source_delete_requests 테이블 부재. 이미 스키마 6이거나 중간 상태이면 중단한다.
- migrator/runtime 역할의 관리자 권한 여부와 runtime 외 동시 DB 클라이언트. 장치·장치 생성 기록·소스·프로필·소스 생성 기록·장치 수정 기록·소스 수정 기록의 7개 건수를 수집한다.
- DB 크기와 호스트 백업 경로 여유 공간. 최소 기준은 DB 크기의 2배와 64 MiB 중 큰 값이다. 실제 덤프 크기나 복원 성공을 보장하지 않으며 이번에는 백업을 생성하지 않는다.
- 점검 전후 컨테이너 ID/이미지/시작 시각/재시작 횟수, 환경·비밀·08 완료 기록·09-C 명세·점검 도구의 해시 일치.

건수는 운영 요청이 계속 가능한 상태에서 조회한 값이며 쓰기를 차단하거나 등록 소스를 수정/삭제하지 않는다. 표시 이름·프로필 원문·토큰·DSN·비밀번호를 보고서나 표준 출력에 남기지 않는다. 환경/비밀 해시·컨테이너/데몬 식별자는 0600 개인 보고서에만 저장한다.

잠금을 획득하면 이전 보고서를 running으로 바꾸고 실패·중단 시 failed로 무효화한다. 다른 작업이 잠금을 잡고 있으면 보고서를 덮어쓰지 않는다. 오류는 상세 Docker 출력 대신 고정 코드로 표시한다. 등록 전용 검사는 현재 코드와 구성의 일치 여부이며 외부 미디어 사용을 탐지하는 검사가 아니다.

## 로컬 검증

- Python 검사 30개 통과. 허용된 읽기 명령만 실행하고 빌드/재시작/삭제/임의 SQL·적용 인자를 차단한다. 스키마 5 이력·체크섬·API·완료 기록·이미지·마운트·역할·다른 DB 클라이언트·7개 건수·백업 공간 불일치 시 중단한다.
- 등록 전용 목표 정책·정책 코드 누락, 현재 API의 미디어 기능 활성·세션/소비/미확인 capability 추가·기능 누락을 거부한다. 점검 중 환경·비밀·컨테이너·완료 기록 변경, 코드 변경·심볼릭 링크, 공유 잠금 충돌과 과거 성공 보고서의 실패/중단 무효화, 0600 보고서·공개 출력 비밀 제외도 확인했다.
- 임시 PGlite에서 스키마 5를 구성하고 고정 읽기 전용 SQL을 실행해 마이그레이션 5개·건수 필드 7개·삭제 기록 테이블 부재의 결과 구조를 확인했다. 실제 PostgreSQL 17/Docker의 운영 사전점검은 서버 실행 결과로 인수한다.
- 실제 09-C 프로젝트 명세·해시 확인과 Python 3.10 문법 검사 통과. 패치 적용/재적용·충돌 시 사전 중단, payload/압축본 경로·해시와 기존 코드·명세·환경·운영 활성화 기록 보존을 확인했다.

Go·HTTP·DB 마이그레이션 코드를 바꾸지 않았으므로 이미 서버에서 통과한 전체 Go/DB 검사와 smoke를 반복하지 않았다. 운영 이미지 빌드·서비스 전환도 수행하지 않았다.
