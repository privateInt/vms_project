통합 검사 첫 실행의 API 종료 시간 초과 후, 검사 클라이언트가 readiness 응답을 끝까지 읽고 종료 전에 유휴 HTTP 연결을 닫도록 보완했다. 이후 연속 WASM 검사에서는 브리지의 ECONNRESET을 관찰했다. API와 저장소 패키지마다 새 WASM DB/브리지를 만든 최종 검사는 모두 통과했다. 이 결과로 실제 PostgreSQL의 역할 인증·동시 세션 검증을 대체하지 않으며, 초기 종료 실패의 전체 원인을 확정했다고 간주하지 않는다. 제작 환경에는 Docker 엔진이 없다.

## 적용과 완료 기준

파일 패치는 단위 04와 완료 기록 적용본을 기준으로 충돌 검사·백업하며 .env·운영 DB·실행 서비스를 변경하지 않는다. 서버에서 기존 test_camera_storage.py로 격리 검사를 수행한다. 최종 성공 scope는 `camera_devices_sources_and_storage_native_postgresql`이며 production_services_modified=false여야 한다.

05-A에는 04단계 활성화 도구나 루트 Compose 재빌드·운영 마이그레이션을 실행하지 않는다. 새 리비전은 04단계 전용 활성화 도구의 검증 대상과 다르며, 기존 검사 성공 기록을 새 코드의 통과로 간주하지 않는다. 운영 장치 API는 기존 이미지와 스키마 2를 계속 사용한다.

서버 결과를 받은 뒤 다음 작업은 **05-B: 새 소스 API의 실제 반영과 호환성·복구 검증**이다. 이때 기존 장치 데이터·멱등 응답 보존, 백업, 스키마 3 및 새 권한, API 전환, 다른 서비스 보존을 확인한다. 스키마 3은 기존 API의 엄격한 readiness와 호환되지 않으므로 구버전 이미지 재사용만으로 복구됐다고 간주하지 않는다. 이후 소스 목록 조회를 별도 기능 단위로 진행한다.
