## 선행 확인과 범위

사용자가 전달한 단위 02 로그에서 20개 파일 적용과 PostgreSQL 17.11 일반 서버 검증 통과를 확인했다. 동시 마이그레이션, 오류 원자성, 기존 테이블 보존을 포함하며 임시 컨테이너·네트워크도 제거됐다. 상세는 단위 02 기록에 추가했다.

AGENTS와 작업 기준·최신 이력·등록 계약을 확인했다. 이번 결과는 Device 생성/단건/목록과 멱등 처리, 선택적 DB 연결 및 API/DB 통합 검사다. 운영 DB 설치·실행 중인 서비스 전환은 서버 격리 결과 확인 뒤 별도 적용 단위로 나눴다. 소스 CRUD·수정/삭제·세션·영상·UI는 구현하지 않았다.

## 변경

- DeviceCreate의 정확한 필드명·타입·중복 키 검사와 의미 검증. 장치 생성/조회/목록, 요청 ID, Location, 201 재생, 404/409/422/503 구분.
- DB 트랜잭션 안에 장치와 성공 응답 저장, 인증 주체·메서드·경로·멱등 키별 잠금. 성공 기록 무기한 보존, 키 자체는 해시로 저장. 고정 개발 주체로 토큰 교체 후에도 재시도 가능.
- ID 오름차순 페이지·불투명 커서·limit 50/최대 200. 삭제 이력 조회 제외, ID 재사용 거부.
- 기존 0001 SQL 보존, 0002 멱등 기록 추가. 단위 02 데이터 보존 업그레이드 검사.
- camera-api의 명시적 DB 연결과 스키마 사전 검사. DB 미설정은 등록 비활성, 잘못된 설정은 시작 실패. DB 연결 시 readiness에 이력·권한 확인 추가. API 자동 DDL 없음.
- 공통 HTTP에는 선택적 readiness callback과 플랫폼 버전/단계만 추가. camera 업무 로직은 camera/internal에 유지.
- OpenAPI·운영 안내·기준 문서 갱신. 기존 검사 도구를 전체 Go 검사와 장치 API/DB 검사로 확장. 테스트용 역할·비밀번호·API 포트는 임시 환경 전용.

## 검증 상태

제작 환경: Linux amd64, Go 1.27.1, pgx/v5 5.11.0, PGlite 0.5.8의 PostgreSQL 18.3 WASM. 일반 PostgreSQL과 Docker 실행은 이 환경에서 제공되지 않는다. 서버의 단위 02 통과를 단위 03의 새로운 코드 검증으로 대체하지 않는다.
