# ADR 0005 — 접속 설정과 비밀 참조의 분리

날짜: 2026-10-02 · 상태: 계획 계약 채택, 구현·운영 적용 전

## 배경

장치·소스 등록/조회/수정/논리 삭제는 API 0.7.0·스키마 7에서 운영 인수를 마쳤다. 등록 DTO에는 URL·username/password·credential_ref가 없으며 등록과 실제 수신을 구분한다. 실제 연결을 도입하려면 소스/프로필의 접속 설정·비밀·사용 예약·삭제 경쟁을 별도 책임으로 관리해야 한다.

## 결정

camera 소유 ConnectionConfig를 source_id+profile_id별 별도 자원으로 정한다. 한 미삭제 설정을 허용하며 ID·부모/프로필·adapter는 불변, endpoint/auth만 version 조건의 전체 PUT으로 교체한다. 첫 계획은 RTSP_PULL·TCP의 메타데이터 계약이다. ONVIF·RTSPS/UDP·XR 시그널링·입력 기술은 별도 검증 뒤 확장한다.

비밀은 CredentialVersion에 두고 설정은 opaque ID+정확한 버전만 참조한다. 같은 Device 권한과 비밀 관리자가 승인한 접속 대상 범위까지 확인한다. 설정 편집자가 임의 endpoint를 지정해 비밀을 다른 대상에 보내는 권한을 얻지 않는다. 새 비밀/대상 정책은 새 버전이며 기존 설정이 latest를 따라가지 않는다.

공개·멱등 응답은 safe metadata만 저장/반환하고 endpoint와 원문 비밀은 제외한다. endpoint/auth 전체 의미의 멱등 비교는 별도 버전 키의 HMAC 지문으로 요구한다. 지문 키·비밀 암호화 키·Bearer/DB 비밀의 분리, 키 부재/교체·옛 응답 재생·복원은 비밀 저장소의 완료 기준이다. 아직 알고리즘 라이브러리·secret backend·키 공급 구현을 선택한 것은 아니다.

설정/부모 삭제 및 실제 사용 시작은 camera의 같은 원자적 허용 경계를 공유한다. 미삭제 설정은 소스 삭제를 막고 설정 교체/삭제는 준비 예약·세션·소비·정리가 해제돼야 한다. 저장 단계에서도 새로운 capability와 부모 삭제 guard를 함께 바꿔야 하며 기존 registry-only-v1 정책에 새 관리 관계를 숨기지 않는다.

장비 네트워크 호출은 메타데이터 CRUD에서 수행하지 않는다. 실제 연결은 운영자 승인 대상·비밀 대상 정책·DNS 주소 검사·고정 dial·redirect 금지·timeout/cancel·비밀 비노출을 별도 검증한 어댑터만 수행한다. 모델/분석/운영 플랫폼은 camera API로 요청하고 비밀 원문·camera DB/internal 코드를 공유하지 않는다.

## 대안과 영향

| 대안 | 판단 |
|---|---|
| Source 생성/수정 DTO에 RTSP URL·비밀번호 추가 | 등록 응답·성공 재생·비밀 회전·런타임 수명이 섞여 제외 |
| URI 형식의 외부 secret 참조를 클라이언트가 지정 | 임의 provider/path 접근과 권한 우회가 생길 수 있어 camera 로컬 식별자로 제한 |
| latest 참조·누락 필드 기반 PATCH | 암묵적 비밀 교체와 재시도 의미 변경을 피하려고 고정 버전·전체 교체 채택 |
| 원문 endpoint를 일반 조회/재생에 반환 | 경로가 비밀이 될 가능성과 원문 노출을 줄이기 위해 메타데이터 응답부터 시작 |
| 설정 삭제와 세션 강제 종료를 묶음 | 정리 불확실·부분 실패를 숨기므로 사용 해제 후 논리 삭제로 분리 |

메타데이터 조회만으로 기존 주소를 편집 화면에 다시 채울 수 없다. 그런 기능이 필요하면 별도 권한·주소 응답/감사 계약을 먼저 정의한다. 제한된 path/host/TCP 범위는 장비 호환성을 줄일 수 있으므로 실제 기술 검증 결과로 명시적인 다음 계약을 추가한다. 이를 이유로 현재 입력을 조용히 확장하거나 runtime_verified=true를 표시하지 않는다.

## 현재 검증과 이행

JSON Schema·합성 예제·정적 계약 검사만 추가한다. 실행 OpenAPI·Go/SQL·Compose·프로젝트 명세·0.7.0 운영 이미지/스키마는 보존한다. 새로운 구조가 운영에 배포된 것으로 표시하지 않는다. 기존 activation/rehearsal 해시의 연속성을 유지한다.

후속 순서는 비밀 저장소/키와 대상 범위 → 설정 저장소·HTTP/부모 삭제 보호 → 별도 운영 전환 → 실제 어댑터/사용 예약·장비 검증이다. 구체적인 [계약](../../contracts/camera-connection-config.md)과 [11-A 진행 기록](../../progress/20261002-step11a-connection-config-contract.md)을 따른다.
