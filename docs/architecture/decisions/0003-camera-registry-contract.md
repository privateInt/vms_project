# ADR 0003 — 장치와 영상 소스의 등록 계약

날짜: 2026-09-29 · 상태: 계약 채택, 런타임·저장소 미구현

## 배경

P0-A에는 소스 입력 검증만 있다. 장치 종류·capabilities와 영상 소스가 하나의 검증 DTO에 함께 있지만 실제 저장 모델이 확정된 것은 아니다. 한 장치에 여러 채널을 등록하고 CCTV와 XR을 함께 관리하려면 장치·영상 소스·접속 세션을 구분해야 한다. 사용자 요청에 따라 등록 계약 확정을 하나의 작업 단위로 끝낸다.

## 결정

- camera가 Device·VideoSource·StreamProfile·후속 ConnectionConfig/SourceSession을 소유한다.
- DeviceCreate와 SourceCreate를 새 생성 입력으로 정의한다. 기존 SourceSpec 검증 API는 유지한다.
- 소스는 안정된 부모 장치 ID와 장치 내 채널 키로 연결한다. IP/포트는 채널 식별자로 사용하지 않는다.
- 장치 종류는 Device에만 저장하고, 실제 기능 지원 여부는 어댑터가 관측한다. 미확인 capability를 미지원으로 단정하지 않는다.
- 일반 등록 요청에서 접속 주소·비밀번호·인증정보 참조를 분리한다. 입력 등록 성공과 실제 연결 성공을 구분한다.
- 생성은 멱등 키와 DB 트랜잭션을 기준으로 설계한다. 물리 DDL·DB 엔진·드라이버는 다음 단위에서 확정한다.
- 구현 전 스키마는 camera의 `api/planned`에 두고 현재 실행 OpenAPI에는 노출하지 않는다.

## 영향과 검증

후속 등록 API는 기존 validate 요청과 형태가 다르므로 자동으로 같은 DTO로 해석하지 않는다. 저장 구조는 소유권과 다중 채널 규칙을 반영하며, 연결·미디어 구현은 해당 계약에 이어 붙인다. 상세 계약·작업 순서는 `docs/contracts/camera-registry.md`에 둔다.

스키마·예제 검사는 입력 형식 검증이다. DB 관계·멱등 트랜잭션·실제 연결은 아직 검증하지 않았으며 각 구현 단위에서 확인한다.
