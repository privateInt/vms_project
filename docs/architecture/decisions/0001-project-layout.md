# ADR 0001 — 저장소 구조와 소유권

날짜: 2026-09-29 · 상태: 채택

## 배경

사용자는 `/home/shshin/workspace/vms_project`에 새 프로젝트를 구성하고, 소스는 `src` 아래의 `platform`·`infra`로, 문서는 `src` 옆의 `docs`로 나눌 것을 요청했다. 플랫폼은 카메라·모델·영상 분석·운영의 독립성을 유지해야 한다.

## 결정

요청한 구조를 채택한다. 플랫폼마다 업무 코드·API·테스트·전용 배포 파일을 소유한다. 공통 인프라와 운영 스크립트는 `src/infra`에 둔다. 설계·ADR·작업 결과는 `docs`에 둔다. 루트에는 설명과 실행 구성 진입점만 둔다.

초기 Go API는 `src/platform/go.mod` 한 개로 관리한다. 실행 파일은 플랫폼별로 분리하고 `internal`을 이용해 업무 코드 접근을 제한한다. 공통 HTTP 코드는 `src/platform/internal/httpapi`에 두되 도메인 계약은 공유하지 않는다.

## 대안과 결과

처음부터 네 저장소·네 모듈을 만들면 독립 릴리스는 쉬워지지만 초기 계약 변경과 기술 기반 수정에 드는 운영 부담이 커진다. 반대로 하나의 실행 파일과 데이터 모델로 합치면 플랫폼별 교체·장애 격리가 어려워진다. 현재는 하나의 저장소에서 실행·업무 경계를 분리한다.

단일 모듈의 의존성·Go 버전은 함께 관리된다. 독립 릴리스 주기나 상충하는 의존성이 실제로 생기면 모듈을 분리한다. 독립 DB와 런타임 자원 격리는 후속 구현이 필요하며 폴더 구조만으로 달성했다고 간주하지 않는다.
