# 소스 목록 이미지 검사 — 단위 06-B1

## 목적과 전제

06-A의 실제 PostgreSQL 격리 검사가 통과한 다음, 배포할 camera 이미지를 별도 Docker 프로젝트에서 확인한다. 운영 전환은 다음 06-B2의 별도 완료 기준이다. 이 도구는 운영 서비스를 시작·중지·재생성하거나 운영 DB를 마이그레이션하지 않는다.

운영 camera는 `0.3.0-source-registry`, DB는 스키마 3이어야 한다. 로컬 코드는 06-A의 `0.3.1-source-list` 명세 및 파일 SHA-256과 일치해야 한다. 운영 `.env`의 camera 이미지 고정값과 실행 중 이미지도 같아야 한다. 예상과 다르면 검사에 실패하며 파일이나 운영 서비스를 수정하지 않는다. 기존 04·05 전용 활성화 도구는 다시 실행하지 않는다.

## 검사 범위

1. 운영 상태·스키마 이력·코드 해시를 조회한다. 운영 Docker 객체는 조회 명령만 허용한다.
2. 명세에 포함된 검증된 파일만 임시 경로로 복사한다. 운영 환경 파일·실행 데이터·백업·비밀은 복사하지 않는다. 별도 토큰·비밀·볼륨·네트워크·루프백 포트를 만든다.
3. 새 camera 이미지를 시험 전용 태그로 빌드한다. PostgreSQL은 운영에서 실행 중인 정확한 이미지 ID를 사용한다.
4. 별도 DB를 이전 camera 이미지의 마이그레이션으로 스키마 3까지 처음 구성하고 장치·소스를 등록한다. 마이그레이션과 권한 부여는 이 시험 DB의 초기 구성에만 수행한다.
5. 새 이미지에서 목록 인증·정렬·전체 프로필·페이지 구분·필터·빈 목록·필터와 cursor의 결합을 확인한다. 새 데이터 등록 후 API 컨테이너를 재생성하고 cursor가 이어지는지 확인한다.
6. 같은 시험 DB에서 이전 이미지로만 복귀해 새 이미지가 등록한 데이터의 조회와 멱등 재요청을 확인한다. 새 이미지로 다시 전환한 뒤 전체 목록과 스키마 3, DB 컨테이너 유지 여부를 확인한다. 이미지 교체 사이에는 마이그레이션·권한 변경·DB 복구를 실행하지 않는다.
7. 시험 컨테이너·볼륨·네트워크를 정리한다. 운영 컨테이너, `.env`, DB 비밀, 코드·검사 도구의 해시가 유지됐는지 확인한 뒤 통과 보고서를 저장한다. 운영 사용자의 정상적인 데이터 등록을 막거나 운영 데이터 건수의 불변을 요구하지 않는다.

## 결과와 보존

보고서는 `var/camera/source-list-image-check.json`에 소유자 전용 권한으로 저장한다. `status=passed`, `scope=camera_source_list_image_native_docker`, `production_services_modified=false`, `source_list_activated=false`가 이번 완료 기준이다. 새 이미지 ID, 이전 이미지 ID, DB 이미지 ID, 코드·검사 도구 해시와 Docker 데몬 식별값을 다음 전환 단계가 검증할 수 있도록 포함한다. 토큰·비밀값은 보고하지 않는다.

통과한 candidate 이미지는 다음 전환에 사용하므로 시험 전용 태그와 함께 남긴다. 컨테이너·네트워크·시험 데이터 볼륨·임시 작업 경로는 정리한다. 정리가 실패하면 성공을 기록하지 않고 `cleanup_failed`와 시험 작업 경로를 출력한다. 이 경우 아직 사용 중일 수 있는 시험 비밀 파일을 보존한다.

검사를 다시 실행하면 새 시험 프로젝트와 보고서를 만든다. 시작할 때 기존 통과 보고서를 `running`으로 바꾸며, 실패하면 `failed`로 기록해 오래된 성공 결과의 사용을 막는다. 강제 종료나 호스트 중단으로 `running`이 남아 있어도 전환 근거로 사용하지 않는다. 실행 중에는 기존 camera 활성화 잠금을 함께 사용한다.

기존 `source-activation.json`, 이전 백업과 검사 보고서는 보존한다. 이 검사의 통과는 소스 목록의 운영 활성화, 실장비 입력 또는 영상 처리 완료를 뜻하지 않는다.
